# i18n 国际化设计规格

## 概述

为 LAN Share 项目添加国际化支持，覆盖桌面端 Tauri 应用（`src/`）和 web 端页面（`src-web/`）。默认检测系统语言，支持用户手动选择。先支持中文和英文，架构预留多语种扩展能力。

## 架构概览

```
                    ┌──────────────────────────────────────┐
                    │        i18n 翻译 JSON 文件             │
                    │  src/locales/     src-web/src/locales/ │
                    │  ├── zh-CN.json   ├── zh-CN.json      │
                    │  └── en.json      └── en.json          │
                    └──────────────────────────────────────┘
                                     ↑ import()
                    ┌──────────────────────────────────────┐
                    │   i18next + react-i18next            │
                    │   i18n.ts (初始化、语言检测、配置)      │
                    └──────────────────────────────────────┘
                              ↑                  ↑
              ┌──────────────┴──┐    ┌───────────┴─────────┐
              │  桌面端 (src/)   │    │  web 端 (src-web/)    │
              │                  │    │                      │
              │ 偏好存储: SQLite  │    │ 偏好存储: localStorage │
              │ IPC: get/set_lang│    │                      │
              └──────────────────┘    └──────────────────────┘
```

**核心原则**：
- 两个项目各自独立维护 locales JSON 文件，不共享翻译文件
- 桌面端通过 `invoke('get_language')` 从 SQLite 读偏好，web 端从 `localStorage` 读
- 翻译 JSON 在构建时打包进产物，运行时通过 `import()` 懒加载
- 以后加语种只需加 JSON 文件，不改代码结构

## 技术选型

| 层面 | 技术 |
|------|------|
| JS i18n 库 | `i18next` + `react-i18next` |
| 翻译文件格式 | 一语言一 JSON 文件，语义化层级 key |
| 动态参数 | i18next 插值语法 `{{varName}}` |
| 桌面端偏好存储 | Rust SQLite `config` 表，key=`language` |
| Web 端偏好存储 | `localStorage`，key=`lan-share-language` |

## 语言检测逻辑

```
应用启动
  ↓
检查用户是否已手动选择过语言？
  ├── 是 → 使用已选语言
  └── 否 → 检测系统语言 (navigator.language)
              ├── 以 "zh" 开头 → zh-CN
              └── 其他所有语言 → en（英文兜底）
```

要点：
- 用户手动选择优先，一旦选择后不再跟随系统语言变化
- 桌面端首次：SQLite 无记录 → 走系统检测 → 写入 SQLite
- Web 端首次：localStorage 无记录 → 走系统检测 → 写入 localStorage
- 再次进入：直接使用偏好值

## i18n 初始化流程

### 桌面端

```
main.jsx 挂载前
  ↓
await invoke('get_language')   ← 读 SQLite config 表
  ↓
有值？ → 使用该值
无值  → navigator.language 检测
          ├── 以 "zh" 开头 → 'zh-CN'
          └── 其他 → 'en'
  ↓
i18next.init({ lng, resources: { ...import 的 JSON } })
  ↓
React 渲染，所有组件可用 useTranslation()
  ↓
用户切换语言 → i18next.changeLanguage() + invoke('set_language')
```

### Web 端

```
main.jsx 挂载前
  ↓
localStorage.getItem('lan-share-language')
  ↓
有值？ → 使用该值
无值  → navigator.language 检测（同上）
  ↓
i18next.init({ lng, resources: { ...import 的 JSON } })
  ↓
用户切换语言 → i18next.changeLanguage() + localStorage.setItem()
```

**注意**：不使用 `i18next-browser-languagedetector` 插件，因为桌面端需要从 SQLite（非浏览器标准存储）读取偏好，两个项目各自实现检测逻辑。

## 翻译文件组织

一个语种一个文件，全部文案放在同一文件中，按页面/功能分语义化层级：

```
src/locales/          # 桌面端
├── zh-CN.json
└── en.json

src-web/src/locales/  # Web 端
├── zh-CN.json
└── en.json
```

### Key 命名规范

- 语义化层级，点号嵌套
- 公共文案放 `common` 命名空间
- 各页面文案按页面名命名
- 动态参数用 `{{varName}}` 插值

## Rust 后端改动

新增 2 个 Tauri IPC 命令，位于 `src-tauri/src/cmd/system.rs`，注册于 `_cmd_handler.rs`：

### `get_language`
- 从 SQLite `config` 表读取 `language` 键的值
- 无记录时返回空字符串（前端据此走系统检测逻辑）
- 签名：`async fn get_language(state: State<'_>) -> Result<String, String>`

### `set_language`
- 写入 SQLite `config` 表的 `language` 键
- 签名：`async fn set_language(language: String, state: State<'_>) -> Result<(), String>`

实现模式参照现有 `get_theme_setting` / `set_theme_setting`。

无需改动 HTTP server 或 Rust 配置系统。

## 语言切换 UI

### 桌面端 — Settings 页面

在「基础」区块的「主题」设置下方新增「语言」行：

```
设置 → 基础
  Http Server端口    3000
  开机自启            [toggle]
  主题               [跟随系统 ▾]
  语言               [中文 ▾]          ← 新增 <select>
```

选项显示当前语言名称（`中文` / `English`），切换后通过 `i18next.changeLanguage()` 立即生效，无需刷新。

### Web 端 — 页面顶部

在主题切换按钮旁边新增语言选择器。样式与现有主题按钮保持一致：

```
[☀ 浅色]  [🌐 中文 ▾]       ← 新增
```

切换后立即生效，偏好存入 `localStorage`。

## 打包注意事项

- **桌面端**：使用 `import()` 懒加载翻译 JSON，Vite 正常处理 chunk
- **Web 端**：使用 `vite-plugin-singlefile` 打包为单 HTML 文件；翻译文件改为编译时静态 `import`（全部语言打包进 bundle，总体积 < 20KB，影响可忽略），避免单文件模式下 chunk 加载失败

## 后续扩展语种

1. 新建 `src/locales/ja.json`（或 `ko.json` 等）
2. 在 `i18n.ts` 的 `supportedLngs` 中追加语种代码
3. 在 UI 语言选择器中追加对应选项
4. 无需改动 Rust 代码、路由、组件结构
